## 1. 主结果

```
                         n         raw      常数基线      macro-recall
  多选题 · 全部      16,404     73.82%      58.54%        71.03%
  多选题 · 单图      14,965     74.53%      59.90%        72.32%
  多选题 · 多图       1,439     66.44%      44.41%        65.53%
  判断题 · 全部       2,804     77.46%      73.57%        66.26%
  ─────────────────────────────────────────────────────────────────
  总体               19,208     74.35%      49.99%        69.44%
```

「常数基线」= 永远输出该题型的多数类答案（多选题选 A / 判断题选「是」）。
**这是及格线，不是零分线。**

## 2. 发现一：raw accuracy 掩盖了判断题的少数类崩溃

判断题看起来最好（raw 77.46%），但拆开看：

```
  真值     n     占比     召回率
  是    2,063   73.6%    90.0%
  否      741   26.4%    42.5%   ← 低于随机猜 (50%)
```

- raw 77.46% vs macro-recall 66.26%，**差 11.20 个百分点**（全数据集中最大）
- 模型在少数类「否」上的召回率 **42.5%，比抛硬币还差**
- 预测分布 是:81.4% / 否:18.5% —— 比真值分布(73.6/26.4)更极端

**结论**：模型在判断题上接近退化为「全选是」，但又不是完全退化
（它答了 520 次「否」，只对 315 次）。

## 3. 发现二：多图题存在清晰的崩溃曲线

```
   图数     n       raw      常数基线      增益
    2     666     75.5%      45.8%      +29.7pp
    3     380     62.4%      44.2%      +18.2pp
    4     227     61.7%      29.5%      +32.2pp
    5      23     87.0%      78.3%       +8.7pp
    6       4     75.0%      50.0%      +25.0pp
    8      60     50.0%      56.7%       -6.7pp   ← 低于基线
   10      78     29.5%      59.0%      -29.5pp   ← 崩溃
   11       1      0.0%     100.0%     -100.0pp
```

**10 张图的题：raw 29.5%，比「无脑全选 A」低 29.5 个百分点**（n=78）。

图数 ≥8 时性能崩塌，说明模型的跨图表整合能力存在明确上限。
这是金融分析的真实场景（对比多期财报），值得深入。

## 4. 发现三：模型的答案偏差方向不一致

```
多选题  多数类「A」 真值 58.5% -> 模型 48.1%   (-10.4pp, 逆着偏差走)
判断题  多数类「是」真值 73.6% -> 模型 81.4%   ( +7.8pp, 顺着偏差走)
```

同一个模型，在两种题型上朝相反方向偏离数据分布。

一个待验证的假设：多选题上模型被 RLHF 训练出「不要总选同一项」的倾向，
而判断题上「是」的语言先验压过了这个倾向。**需要额外实验才能确认，此处仅记录现象。**

## 5. 发现四：数据集本身存在标注缺陷

模型输出多个字母（`ABCD` / `ABC` / `AB`）共 55 条，全部被现有提取规则判为错误。
逐条检查发现：

- 这 55 条**全部**是「以下**哪些**……」句式（例：*以下哪些机构直接或间接持有…的股份？*）
- 「哪些」在这批中占 87%，而全量数据中只占 8.10% —— **富集 10.8 倍**
- 但 gold 只标注了单个字母（如 `A`）

**这些不是模型的错误，是标注格式与问题语义不匹配。**
多选题问「哪些」却只有单选答案，本身是矛盾的。

占比 0.33%，量不大，但属于系统性缺陷。

## 7. 附加实验：prompt 敏感性验证

> 目的：确认发现一（判断题少数类召回率 42.5%）是模型性质，还是单一 prompt 的假象。
> 运行：2026-09-11 12:06–12:37 · 4×RTX4090 · 6 个变体 · 约 17k 次推理
> 原始预测：`results/sensitivity/{tf,mc}_{base,nobias,correct_wrong,ab_format}/`

### 7.1 判断题（n=2804 × 4 变体）

```
变体                                     raw      常数基线    macro     是召回    否召回
base (baseline 措辞)                  77.5%     73.6%     66.3%    90.0%    42.5%
nobias (显式提示不要默认选「是」)          76.6%     73.6%     67.9%    86.5%    49.3%
correct_wrong (用「正确/错误」)         76.5%     73.6%     73.0%    80.4%    65.6%
ab_format (转成 A/B 选项)              77.5%     73.6%     72.3%    83.3%    61.3%
```

逐样本配对比较（相对 base，同一 uid）：

```
变体                    翻对    翻错    净变化
ab_format              175    175      +0
correct_wrong          179    206     -27
nobias                  55     78     -23
```

**结论 A —— 少数类崩溃是模型性质，不是 prompt 假象。**
四个变体下「否」召回率全部显著低于「是」（差 22~48 个百分点）。

**结论 B —— 但 prompt 的影响大到足以推翻结论。**
仅把「是/否」换成「正确/错误」，少数类召回率就从 **42.5% 提升到 65.6%**，
macro-recall 从 66.3% → 73.0%。**换个词就暴露出 6.7 个百分点的真实能力差异。**

**结论 C —— raw accuracy 与 macro-recall 方向相反。**
所有变体的 raw 都不优于 base（净变化 −27 / −23 / 0），但 macro-recall 提升最多 6.7pp。
**只按 raw accuracy 调 prompt，会选出少数类召回率最低的那个版本。**

**结论 D —— `nobias` 失效。**
显式告诉模型「正确答案不一定是是，别默认选是」，净变化 **−23，反而变差**。
说明这不是「模型不知道要平衡」，而是**它做不到**。

### 7.2 多选题（n=3000 × 2 变体）

```
变体              raw      常数基线    macro     A       B       C       D
base            73.4%     59.8%     70.5%   73.0%   77.9%   68.7%   62.4%
nobias          72.1%     59.8%     70.1%   70.2%   79.5%   69.3%   61.5%
```

换措辞只影响 1.3pp。

**结论 E —— 题型对 prompt 的敏感度差异巨大。**
多选题对措辞不敏感（<1.5pp），判断题极度敏感（macro 差 6.7pp）。
**这意味着两类题型的评测可信度不同：判断题的结论必须固定 prompt 并同时报告 macro。**

## 8. 附加实验：LoRA 微调能否修复少数类崩溃？

> 运行：2026-09-11 · 4×RTX4090
> 基座 `Qwen3-VL-8B-Instruct`，LoRA r=16 α=32，`freeze_vit=true`，2 epoch
> 评测：同一批 **2,889 条 test 样本**（按来源研报切分，与训练集零重叠）
> 原始预测：`results/posttrain_{zeroshot,lora_natural,lora_balanced}/`

### 8.1 主结果

```
条件                      多选raw    判断raw   判断macro   「否」召回 [95% Wilson CI]
zero-shot (基座)         73.70%    75.23%    63.73%    39.7% [31.2, 48.8]
LoRA natural            84.13%    84.01%    79.15%    69.0% [60.1, 76.7]
LoRA balanced           82.78%    84.01%    79.43%    69.8% [60.9, 77.4]
```

**「否」召回率的两个置信区间完全不重叠**（[31.2, 48.8] vs [60.1, 76.7]）。
微调把 zero-shot 上「低于随机猜」的少数类召回率拉到了 69%。

### 8.2 逐样本配对比较（同一 uid）

```
对比                              翻对   翻错    净变化   McNemar
zero-shot -> LoRA natural         430    136    +294    p < 0.001 ***
zero-shot -> LoRA balanced        428    167    +261    p < 0.001 ***
LoRA natural -> LoRA balanced      84    117     -33    p = 0.024 *
```

在「否」子集（n=116）上：

```
zero-shot -> LoRA natural          40      6     +34
zero-shot -> LoRA balanced         44      9     +35
LoRA natural -> LoRA balanced       9      8      +1
```

### 8.3 关键发现：增益几乎全部落在少数类上

```
                     zero-shot -> LoRA natural
「是」召回 (n=328)      87.8%  ->  89.3%     +1.5pp
「否」召回 (n=116)      39.7%  ->  69.0%    +29.3pp
```

整体净提升 +294/2889 = +10.2pp，而少数类提升 +29.3pp。
**微调不是在均匀地提升所有题，而是专门修复了模型忽略少数类的问题。**

### 8.4 负结果：类别均衡采样没有帮助

`balanced` 条件把训练集的 6 个（题型 × 标签）组合各上采样到 6,725 条，
完全均衡。结果：

- 多选 raw：natural 84.13% vs balanced **82.78%** —— balanced 反而**低 1.35pp**（p=0.024）
- 判断题「否」召回：69.0% vs 69.8% —— 差异在噪声内（配对净变化 +1）

**结论：少数类崩溃不是「训练数据标签不平衡」造成的。**
普通的、按原始分布训练的 SFT 就能修复它，不需要重采样。
均衡采样不仅没帮上忙，还略微损害了多选题的准确率。

一个可能的机制：微调让模型学会了「读图答题」这个任务本身，
从而降低了对外部语言先验的依赖 —— 少数类召回率的提升是这件事的副产品，
而不是靠喂更多少数类样本换来的。**此机制尚未被直接验证，仅为推测。**
